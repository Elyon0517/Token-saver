# Catalog-Derived Spark Priority Producer

Every submission and every dynamic task-graph node receives a deterministic `0-100` score: `0-24` small, `25-49` standard, `50-74` complex, and `75-100` advanced. A low-risk, low-ambiguity text/code/write/execute node in the small band tries the catalog priority producer first even when its parent task is complex or advanced. Today that role resolves to `gpt-5.3-codex-spark|low`; replacement or removal does not break the quality ladder. Spark also remains valid for explicitly admitted disjoint read-only source branches.

Spark stays outside the quality ladder but is a valid schema-version-2 `dynamic_task_graph` result node when its own score is 0-24, modality is text, risk and ambiguity are low, and its bounded purpose is code authoring, edit, command, execution, probe, transform, or write. Its dependency position may be root or downstream. A zero-result, zero-token operational failure falls back to the node's quality pair. An Ending correctness/quality failure records an upgrade, suppresses Spark for the matching project/task/operation/code-kind/score-band context, and makes the next matching task use the contextual quality pair. Other quality pairs retain the two Real PASS downgrade and one quality FAIL upgrade rules.

A model label or cached capability is not execution proof. Require one route receipt containing every attempt, score/band, switch direction, and sanitized `model_learning_context`. Start Ending with `--producer-receipt`; every lifecycle stores score/band locally and the receipt-backed terminal event records the outcome and next pair in Obsidian. Old local `model_experience.json` remains legacy read-only. Present the completed result first; Ending Real runs independently and a different Ending verifier confirms any repair.
